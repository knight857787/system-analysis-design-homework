## 二、执行步骤（按实际顺序）

### 1. SSH 密钥登录

```bash
# admin 用户 sudo 写 root 的 authorized_keys（重定向要用 tee，不能用 sudo echo >>）
PUB='ssh-ed25519 AAAA... oc-deploy-20261118'
printf '%s\n' "$PUB" | sudo tee -a /root/.ssh/authorized_keys >/dev/null
sudo chmod 700 /root/.ssh && sudo chmod 600 /root/.ssh/authorized_keys
# 客户端：
ssh -i oc_deploy_ed25519 root@101.201.222.69
```

### 2. 上传源码（tar，不要 zip）

```powershell
# Windows 侧：PowerShell 的 Compress-Archive 会把路径写成反斜杠，Linux 解压后目录结构全废
tar -czf app.tar.gz --exclude=__pycache__ --exclude="*.pyc" -C "…\作业\系统源代码" .
scp -i oc_deploy_ed25519 app.tar.gz root@101.201.222.69:/tmp/
```

```bash
# 服务器侧
mkdir -p /app/workspace && tar -xzf /tmp/app.tar.gz -C /app/workspace
```

> 踩坑实录：先用 `Compress-Archive` 传过一次，解压后文件名变成 `server\core.py`（字面反斜杠），
> `server/` 目录不存在 → 应用报 `ModuleNotFoundError: No module named 'server'`。改用 tar 后正常。

### 3. 应用托管（systemd，仅监听 127.0.0.1）

```bash
useradd -r -s /sbin/nologin -M ocapp
mkdir -p /www/wwwroot/oc-emporiumretai-ms.com/{app,data,backup}
cp -a /app/workspace/. /www/wwwroot/oc-emporiumretai-ms.com/app/
cp -a /www/wwwroot/oc-emporiumretai-ms.com/app/data/store.db /www/wwwroot/oc-emporiumretai-ms.com/data/
chown -R ocapp:ocapp /www/wwwroot/oc-emporiumretai-ms.com && chmod 750 …/data
install -m 644 conf/store-assistant.service /etc/systemd/system/   # 占位符已替换
systemctl daemon-reload && systemctl enable --now store-assistant
```

unit 关键环境变量：`APP_HOST=127.0.0.1 PORT=19870 STORE_DATA_DIR=…/data COOKIE_SECURE=1`。

### 4. Nginx 反代

```bash
dnf install -y nginx
mkdir -p /etc/nginx/ssl/oc-emporiumretai-ms.com
# 先放自签名证书，保证 nginx 能起（否则 nginx -t 因证书缺失失败）
openssl req -x509 -nodes -newkey rsa:2048 -days 30 \
  -subj "/CN=oc-emporiumretai-ms.com" \
  -keyout /etc/nginx/ssl/oc-emporiumretai-ms.com/privkey.pem \
  -out    /etc/nginx/ssl/oc-emporiumretai-ms.com/fullchain.pem
# vhost 写入 /etc/nginx/conf.d/oc-emporiumretai-ms.com.conf（内容见 conf/nginx_*.conf 的 B 版）
nginx -t && systemctl enable --now nginx
```

**80 端口块的关键顺序**：ACME 校验路径要放在 `location` 里，301 只能写在 `location /` 内：

```nginx
location ^~ /.well-known/acme-challenge/ { root /www/wwwroot/oc-emporiumretai-ms.com; try_files $uri =404; }
location / { return 301 https://$host$request_uri; }
```

> 踩坑实录：把 `return 301` 写在 server 级，会先于 location 执行，ACME 校验路径也返回 301，
> 证书申请必然失败（实测 `challenge http=301`）。

### 5. 证书（acme.sh）

```bash
curl -fsSL https://cdn.jsdelivr.net/gh/acmesh-official/acme.sh@master/acme.sh -o /root/.acme.sh/acme.sh
chmod +x /root/.acme.sh/acme.sh
/root/.acme.sh/acme.sh --set-default-ca --server letsencrypt
/root/.acme.sh/acme.sh --issue -d oc-emporiumretai-ms.com -d www.oc-emporiumretai-ms.com \
    -w /www/wwwroot/oc-emporiumretai-ms.com --keylength 2048 --server letsencrypt
/root/.acme.sh/acme.sh --install-cert -d oc-emporiumretai-ms.com --keylength 2048 \
    --key-file /etc/nginx/ssl/oc-emporiumretai-ms.com/privkey.pem \
    --fullchain-file /etc/nginx/ssl/oc-emporiumretai-ms.com/fullchain.pem \
    --reloadcmd "systemctl reload nginx"
```

实测结果：`issuer=Let's Encrypt CN=YR1`、`SAN=oc-emporiumretai-ms.com,www.oc-emporiumretai-ms.com`、
有效至 2027-02-16；客户端 `ssl_verify_result=0`（用系统 CA 校验通过）。

> 说明：`raw.githubusercontent.com` 与 `github.com` 从该机不可达（curl 0 字节），
> `cdn.jsdelivr.net`、`gitee.com` 可达；acme.sh 官方安装脚本 `get.acme.sh` 也会卡住。

## 三、备案与 HTTP 拦截（2026-11-18 17:10 起，重要）

**现象**：公网 `http://oc-emporiumretai-ms.com/` 返回 `403`，响应头 `Server: Beaver`，页面标题
`Non-compliance ICP Filing`，并跳转 `https://www.aliyun.com/beian/beian-block?id=00000000006024766796`。
服务器本机 `curl -H "Host: …" http://127.0.0.1/` 正常返回 301，说明拦截发生在**阿里云网络侧**，不是服务器配置问题。

**原因**：域名备案尚在审核中（阿里云备案单号 2030884515929，2026-11-18 13:04 提交，
`阿里云初审：审核中`，`待提交管局/工信部短信核验/管局审核：未进行`）。阿里云对未完成备案的域名
在 **80 端口**强制拦截；443 不拦（无法对密文插入页面）。

**时间线实测**：17:06 证书签发成功（当时 80 未拦）；17:09:53 `http → 301` 仍正常；
17:11 起 `http → 403`。拦截是在这 1~2 分钟内生效的。

**影响**：

1. 普通用户输入域名先走 `http://`，会看到备案拦截页；用 `https://` 直链可正常访问。
2. **证书续期会失败**：acme.sh 用 HTTP-01（webroot），需要 CA 从公网访问 80 端口的校验文件，
   而现在 80 一律 403。实测为 `dsh.oc-emporiumretai-ms.com` 签发时报
   `Invalid response … 403`。当前证书有效期至 2027-02-16，若届时仍未备案，续期会中断。
3. `dsh.oc-emporiumretai-ms.com` 同样被拦，且不在现有证书 SAN 内，暂时不可用。

**处置**：

- 短期：等备案通过（管局审核 1–20 个工作日，阿里云初审当天 20:00 前），拦截解除后自动恢复；
- 长期（推荐）：改用 **DNS-01** 验证（阿里云 DNS API），完全绕开 80 端口，续期更稳；
  需一个仅有云解析权限的 RAM 子账号 AccessKey；
- 或直接从阿里云申请免费 SSL 证书（nginx 格式）导入，90 天手动换一次。
